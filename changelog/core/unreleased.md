### Added

- `logF[F]` gives the logger of `@Slf4s` with calls in any effect `F` with `Sync`, as a `LoggerF[F]`, for code in `Resource[IO, *]`, `EitherT[IO, E, *]` or polymorphic code; `logF.info(...)` still returns `IO[Unit]` (COILIX-00033).
- IoC container with constructor injection, `@Component`, `@Service`, `@Repository`, `@Qualifier`, `@Primary`, `@Order`, and `Option[T]` and `List[T]` dependencies (COILIX-00000).
- `@Slf4s` compiler plugin that adds an SLF4J `log` field (COILIX-00000).
- Application startup with `@CoilixApplication`, `ApplicationRunner`, command-line arguments and a banner (COILIX-00002). An application is an object that extends `CoilixIOApp`, an `IOApp` of cats-effect, which closes the context when it is cancelled, for example by `SIGTERM` (COILIX-00031).
- Configuration from HOCON, YAML and properties files, command-line options and system properties, `@Value`, `@ConfigurationProperties`, `@Configuration` with `@Bean`, and replacement of framework components through a `class` key under their `coilix.*` path (COILIX-00003).
- Bean lifecycle callbacks: `@PostConstruct` methods run after a bean is created and before it is injected, and `@PreDestroy` methods run in reverse creation order when the context closes. Both may be private (COILIX-00004).
- Optional modules: a `CoilixModule` listed in `META-INF/services/dev.coilix.context.CoilixModule` adds its components to the context when it is on the classpath, and `coilix.modules.<name>.enabled = false` disables it (COILIX-00010).
- Profiles: `coilix.profiles.active` (also `--coilix.profiles.active=dev,local`), `@Profile` with `!` negation, and `application-<profile>.*` files that override `application.*` (COILIX-00014).
- Conditional beans: `@ConditionalOnProperty`, `@ConditionalOnClass` and `@ConditionalOnMissingBean`, checked before dependencies are resolved, so a left-out bean causes no ambiguous or missing dependency (COILIX-00014).
- `EditOption[T]` for partial updates, which tells a field that stays unchanged (`NoEdit`) apart from a field that is set (`SetTo(Some(value))`) or cleared (`SetTo(None)`) (COILIX-00022).
- `Validator[T]` with `Violation`, `ViolationTemplate` and `ValidationException`, which checks every rule of a value and reports all broken rules at once. `Violation("...")` and `ViolationTemplate("... %s")(...)` take their code from the name of the `val` and fail compilation for a malformed message or template (COILIX-00022).
- `@ValueType` for classes that wrap one value, with `ValueTypeResolver` to create them from their inner value, and `Secret`, a value type for passwords and tokens that `toString` hides (COILIX-00022).
- `@Enumerated` for Scala 3 enums read and written by name, `@EnumName` for a custom case name with older aliases, and `EnumResolver`, which looks up cases by name and lists the allowed names when a name is unknown (COILIX-00022).
- `@Value` and `@ConfigurationProperties` accept `@ValueType` classes, `Secret` and `@Enumerated` enums, also inside `Option` and collections. An invalid value stops the startup with the configuration path and the reason (COILIX-00022).
- `coilix-testkit` for munit tests: `CoilixTestSetup` with properties and profiles that win over every other source, `replaceBean` and `addBean`, command-line arguments and optional runners, `setup.use { ... }` and the `CoilixSuite` trait that run test bodies with the context given to them, helpers such as `bean[T]`, `beans[T]` and `property[T](path)` that take the context from `using`, and the explicit `CoilixFixtures` with a context per test or per suite that is closed afterwards (COILIX-00013).
- A `CoilixModule` can collect classes marked with its own annotations through `collects`. Such classes are not beans: the module gets them from the `CollectedComponents` bean, creates them with their dependencies, `@Value` parameters and `@PostConstruct` methods, and closes them to run `@PreDestroy`. A class with a component annotation and a collected one fails the startup with `CollectedComponentConflictException`, and a bean that injects a collected class fails with a `NoSuchBeanException` that says why (COILIX-00026).
- Beans are matched by their full type with type arguments, so `Repository[IO]` and `Repository[Option]` are different beans for constructor parameters, `Option[T]` and `List[T]` dependencies, `getBean`, `BeanReplacements` and the testkit. `TypeInfo[T]` carries the full static type to runtime, and `RegisteredBean.of[T]` registers a ready instance with it. A dependency with an unbound type variable or a type lambda fails with `UnsupportedDependencyTypeException` (COILIX-00020).
- Bean creation is planned before any bean is created: `ContextPlanner` returns a `ContextPlan` with the ready instances and the beans in dependency order, so another interpreter can run the same plan. A `@Bean` method returning `cats.effect.IO[A]` or `cats.effect.kernel.Resource[F, A]` gives a bean of type `A`, recognized by name through the replaceable `EffectfulResultRecognizer`. The synchronous builder rejects such beans with `EffectfulBeanException` until an effect module runs them (COILIX-00020).
- New core module `coilix-concurrency`, included with `coilix-boot`: a `TaskExecutor` bean that runs each task on a new virtual thread (a platform thread on JDK 17, or a fixed pool with `coilix.concurrency.executor.virtual-threads = false`) and a `TaskScheduler` bean for delayed, fixed-rate and fixed-delay tasks. Both are closed with the context, wait up to `shutdown-timeout` for running tasks and then interrupt them. An application `TaskExecutor` marked `@Primary` replaces the default one (COILIX-00005).
- `@Scheduled(fixedRate = ..., fixedDelay = ..., initialDelay = ...)` runs a bean method repeatedly on the task scheduler. Durations are text such as `"10s"` or a placeholder such as `"${shop.refresh:1m}"`. The runs start when every bean exists and stop before any bean is destroyed, and an invalid method stops the startup with `InvalidScheduledMethodException` (COILIX-00005).
- `@Async` runs a bean method on the task executor: a `Future` result comes from the run, and a `Unit` method is started without waiting. The method must be declared in a trait, because the bean is registered as a proxy of that trait; otherwise the startup stops with `InvalidAsyncMethodException`. Modules can change bean definitions before planning through `CoilixModule.definitionProcessors`, and `@PostConstruct` and `@PreDestroy` methods of a proxied bean (`ProxiedBean`) run on the instance behind the proxy (COILIX-00005).
- `ContextLifecycleListener` beans are told when every bean of the context exists (`onContextStarted`) and when the context starts closing, before any `@PreDestroy` method (`onContextClosing`) (COILIX-00005).
- The context closes in phases, whatever the order in which beans were created: `ContextLifecycleListener.closingPhase` puts a listener in `ClosingPhase.Producers` (the default, where `@Scheduled` methods stop), `Events` or `Resources`, and `@PreDestroy` methods run after the last phase (COILIX-00016).
- `RetryPolicy` in `coilix-concurrency` computes the waits between tries of failed work: a number of tries, an exponential wait with a limit and a random spread. `RetryPolicy.default`, `fixed` and `none` are ready-made, and every parameter has a default, so configuration sets only the keys it changes (COILIX-00016).
- New core module `coilix-events`, included with `coilix-boot`: `EventPublisher` (and `Events.publish` with a `using` publisher) publishes in-memory application events to `@EventListener` methods and `ApplicationEventListener[E]` beans, matched by the full event type with subtypes and type arguments. Listeners run in the thread of the publisher, whose `publish` throws their first failure, or with `@EventListener(async = true)` on the task executor, with optional retries under `coilix.events.listeners.<bean>.<method>.retry`. Events published before the start wait for the listeners. When the context closes, the `EventBus` refuses events from outside listeners with `EventBusClosedException` and waits up to `coilix.events.shutdown-timeout` for the running asynchronous listeners. An invalid listener stops the startup with `InvalidEventListenerException` (COILIX-00016).
- Events of the framework: `ContextReady` before the first `ApplicationRunner`, `ApplicationStarted` after the runners, `ContextClosing` when the context starts closing, before `@Scheduled` methods stop, and `ApplicationFailed` with the exception when a runner or a listener of the startup events fails. `ClosingPhase.Announcement` is a new first phase of closing, in which `ContextClosing` is published (COILIX-00016).
- `coilix.events.synchronous = true` runs asynchronous listeners in the thread of the publisher. The testkit sets it with `CoilixTestSetup.withSynchronousEvents`, records every published event in the `EventRecorder` bean read with `recordedEvents[E]`, and waits for asynchronous listeners with `awaitEvents()`. Test contexts publish `ContextReady` and `ApplicationStarted` like an application (COILIX-00016).
- Fatal errors (`VirtualMachineError` such as `OutOfMemoryError`, and `LinkageError`) thrown in tasks of the `TaskExecutor` and the `TaskScheduler`, in asynchronous event listeners and, in an application started as a `CoilixIOApp`, in any thread go to the `FatalErrorHandler` bean. By default it closes the context on a new thread and ends the process with exit code 70, and halts the process when closing takes longer than `coilix.fatal-errors.shutdown-timeout` (15 s). `coilix.fatal-errors.action = log` only logs them. A custom handler marked `@Primary` replaces the default one, and the `ProcessTerminator` bean can be replaced in tests. Test contexts only log fatal errors unless the setup sets the action (COILIX-00030).
- The startup warns when the JVM runs without `-XX:+ExitOnOutOfMemoryError` or `-XX:+CrashOnOutOfMemoryError`, or, in a container, with a maximum heap smaller than half of the memory limit (COILIX-00030).
- `BlockingExecutor` for calls that wait (JDBC, HTTP, files): a new virtual thread per task, a pool of up to `coilix.concurrency.blocking.platform-threads` platform threads on JDK 17, and an optional `coilix.concurrency.blocking.max-concurrency` limit. `@Async(blocking = true)`, `@EventListener(async = true, blocking = true)` and `ApplicationEventListener.blocking` run on it (COILIX-00005).
- `@ConditionalOnMissingBean` takes the types to look for in `value`, so a default declared with its concrete class gives way to any bean of a broader type (COILIX-00005).
- Tasks keep the SLF4J MDC of the thread that submitted or scheduled them, on both executors, the scheduler, `@Async` methods and asynchronous event listeners, and pooled threads get their own MDC back afterwards. `coilix.concurrency.propagate-mdc = false` turns it off. Other thread-bound values travel the same way through `ContextPropagator` beans (COILIX-00005).
- `@Prototype` creates a bean anew for every lookup and `@Lazy` creates a singleton on its first use, on a component class or a `@Bean` method. A `Provider[T]` constructor parameter gives the bean when `get()` is called, which breaks a dependency cycle and gives a new prototype each time; a missing bean still stops the startup. A singleton that injects a prototype directly is reported as a warning. Lazy beans not created yet are not searched for `@EventListener` and `@Scheduled` methods, and prototypes are not destroyed by the context (COILIX-00015).
- New core module `coilix-cluster` with a `ReplicaIdentity` bean that tells the number of this replica and the number of replicas. `coilix.cluster.identity` selects `single` (the default), `static` (from `coilix.cluster.replica-index` and `coilix.cluster.replicas` or `COILIX_REPLICA_INDEX` and `COILIX_REPLICAS`) or `stateful-set` (from `COILIX_POD_INDEX` or the end of the pod name). A missing or out-of-range number stops the startup with `ReplicaIdentityException` (COILIX-00027).
- `CoilixBootstrap.start` with `BeanReplacements` leaves out discovered beans of the replaced types, and fails with `UnmatchedBeanReplacementException` when a replaced type matches no bean (COILIX-00013).
- `@DependsOn(Array("name"))` on a component class or a `@Bean` method creates the bean after the named beans and destroys it before them, without injecting them. A lazy bean named there is created first, and a name that matches no bean or names a prototype stops the startup (COILIX-00020).
- `CoilixModule.effectInterpreter` lets one module create the beans made by effects: the `EffectInterpreter` gets the levels of the plan from the first one with such a bean, and the context releases what it opened when it closes, before the other beans are destroyed. `ContextPlan.levels` groups the beans by dependency level (`DependencyResolver.resolveLevels`), and `BeanInstantiator` splits into `produce` (the result of the factory) and `complete` (lifecycle and post-processing of the value). Two modules with an interpreter stop the startup with `ConflictingEffectInterpretersException` (COILIX-00020).
- `@ShutdownTimeout("2m")` for a `@Bean` method sets how long closing waits for the finalizer of a bean made by an effect (COILIX-00020).
- `RunnerAdapter` beans add runners of another kind, such as `IOApplicationRunner`, to the list of `ApplicationRunner` beans ordered by `@Order`. A lifecycle method may return an effect of `Unit` recognized by the `EffectfulResultRecognizer`, such as `IO[Unit]`; such a bean is effectful, so the synchronous builder rejects it with `EffectfulBeanException` until an effect module runs it (COILIX-00020).
- `CoilixApplicationRunner.start` builds the context with extra ready beans and returns a `StartedApplication` without runners, for a start that runs them itself. `OrderedRunner.all` gives the runners of a context in their order, and `StartupEvents.ready`, `started` and `failure` publish the startup events one by one (COILIX-00020).
- New core module `coilix-diagnostics`, included with `coilix-boot`. The `Health` bean combines `HealthIndicator` beans into liveness and readiness (`Up`, `Degraded`, `Down`) and publishes `HealthChanged` when one of them changes. The `coilix-diagnostics` platform thread checks the platform threads every `coilix.diagnostics.interval`: `ThreadCheck` beans find deadlocks, too many threads, threads blocked on a monitor for long and a fast growth of the thread count, and the `FindingReporter` bean logs the findings with stacks, repeating warnings of one kind only after `repeat-after`. Deadlocked threads end the application through the `FatalErrorHandler` with `ThreadDeadlockException`, or, with `coilix.diagnostics.threads.on-deadlock = report`, set the `threads` liveness indicator to `Down` (COILIX-00030).
- cats-effect in the core, included with `coilix-boot`: the `IORuntime` of the application as the `ioRuntime` bean, with the work-stealing pool of cats-effect sized by `coilix.concurrency.compute.threads`, shut down with the context. Its compute pool is the only compute pool of the application: the `ioTaskExecutor` bean is the `TaskExecutor`, left out when the application provides its own. A shutdown of the runtime after a fatal error in a fiber goes to the `FatalErrorHandler` as `IORuntimeStoppedException`, and `IO.onBlockingExecutor` runs a blocking call on a virtual thread of the `BlockingExecutor` (COILIX-00020).
- `@Bean` methods may return `IO[A]` or `Resource[IO, A]`: other beans receive the value `A`. The beans are created with one `unsafeRunSync` on the `ioRuntime` bean, independent ones at the same time, level by level, and resources close in the reverse order when the context closes, each finalizer within `coilix.cats-effect.shutdown-timeout` (30 s) or its `@ShutdownTimeout`; a slow finalizer is cancelled and a failing one logged, and closing goes on. A failing effect closes the resources opened before it and stops the startup. A lazy or prototype bean made by an effect stops the startup with `InvalidEffectfulBeanException` (COILIX-00020).
- `@PostConstruct` and `@PreDestroy` methods may return `IO[Unit]`. The `IO` of a `@PostConstruct` method runs after the methods that return `Unit` and before the bean is injected, and a failure stops the startup with `BeanCreationException`. The `IO` of a `@PreDestroy` method runs before the methods that return `Unit`, within the limit of the bean, and a failure is logged. Such a bean cannot be `@Lazy` or `@Prototype` (COILIX-00020).
- `IOApplicationRunner` describes the startup logic as `IO[Unit]`. Its beans run in one list with the `ApplicationRunner` beans, ordered by `@Order`, through the `ioRunnerAdapter` bean (COILIX-00020).
- `CoilixIOApp` starts an application as an `IOApp`: its runtime, with `coilix.concurrency.compute.threads` compute threads, is the `ioRuntime` bean, the runners run in `IO` and the application runs until it is cancelled, which closes the context. `coilix.cats-effect.exit-after-runners = true` closes and ends it after the runners. `CoilixIOStartup` gives the same start as a `Resource` and an `IO` for a given runtime. When the context already has an `IORuntime`, Coilix creates no runtime of its own (COILIX-00020).
- `coilix-testkit` supports tests in `IO`, with munit-cats-effect as a provided dependency: `CoilixIOSuite` for a `CatsEffectSuite` registers `coilixTest` bodies that return `IO` and get a fresh context, whose `ioRuntime` bean is the runtime of the suite. `setup.useIO { ... }`, `setup.resource` and `setup.withIORuntime(runtime)` use a `CoilixTestSetup` in `IO` (COILIX-00020).
- fs2 is part of the core: `coilix-concurrency` depends on `fs2-core`, so applications can write streams as `fs2.Stream[IO, _]` running on the compute pool of the cats-effect runtime (COILIX-00032).
- The `startup` readiness indicator is `Down` while the application starts and `Up` after its runners, and `Down` again after a failed start (COILIX-00031).
- `CoilixIOApp` logs the process identifier at the start, a line when it is asked to stop and a failed start once before ending with exit code 1. Warnings of cats-effect about a starved compute pool and failures it reports go to the log, and `coilix.cats-effect.blocked-thread-detection` turns on the detection of blocked compute threads (COILIX-00031).
- `@Slf4s` also adds `logF`, an `IOLogger` whose `trace`, `debug`, `info`, `warn` and `error` return `IO[Unit]` and build the message only when the level is enabled, so code in `IO` logs without wrapping `log` in `IO(...)` (COILIX-00033).

### Changed

- **BREAKING** `@Scheduled` methods return `IO[Unit]` and run on fibers of their own that wait with `IO.sleep`, cancelled in the `Producers` phase of closing; a failed run is logged and the schedule goes on. The `TaskScheduler` bean is removed with `ScheduledTask`, `ScheduledExecutorTaskScheduler`, `SchedulerSettings` and the keys `coilix.concurrency.scheduler.*`, and `ScheduledMethodRegistrar.activeTasks` returns `IO[Int]`. Migration: return `IO[Unit]` from `@Scheduled` methods (`IO.blocking` for a call that waits), replace code scheduling with an fs2 stream such as `Stream.fixedDelay` on a fiber started by a `ContextLifecycleListener`, retry with `IO.sleep(policy.delayAfter(attempts))`, and drop `coilix.concurrency.scheduler` from the configuration (COILIX-00031).
- **BREAKING** `@Async` methods return `IO`. A call through the proxy returns an `IO` that calls the bean when it runs, on the compute pool or, with `blocking = true`, on the `BlockingExecutor`. A method returning `IO[A]` gives its result to the caller; a method returning `IO[Unit]` is started on a fiber of its own, kept by the new `AsyncTasks` bean, which logs its failure and cancels it in the `Producers` phase of closing. The proxy no longer depends on the `TaskExecutor`. Migration: return `IO[A]` instead of `Future[A]` and `IO[Unit]` instead of `Unit` from `@Async` methods, and compose the result with your `IO` code instead of `IO.fromFuture` (COILIX-00031).
- **BREAKING** The event bus runs on `IO`. `EventPublisher.publish` returns `IO[Unit]` and `tryPublish` returns `EitherT[IO, PublishError, Unit]`; `@EventListener` methods and `ApplicationEventListener.onEvent` return `IO[Unit]`. Synchronous listeners run in the fiber of the publisher, asynchronous ones on fibers of their own under a `Supervisor`, which start with the MDC of the publisher when `coilix-logging` is used, and retries wait with `IO.sleep`; closing cancels the deliveries that run longer than `coilix.events.shutdown-timeout` instead of interrupting threads. `blocking` is removed from `@EventListener` and `ApplicationEventListener`, the bus no longer needs the `TaskExecutor`, `BlockingExecutor` and `TaskScheduler`, `EventBus.listeners`, `pendingDeliveries` and `awaitIdle` return `IO`, and `Health.refresh` returns `IO[Unit]`. `close()` of a context closes it on the global runtime of cats-effect. Migration: return `IO[Unit]` from listeners (`IO.blocking` for a call that waits, in place of `blocking = true`), run `publish` in your `IO` code, and publish from a `@PostConstruct` method that returns `IO[Unit]` instead of a constructor (COILIX-00031).
- **BREAKING** `EventPublisher` gets `tryPublish`, which returns `Either[PublishError, Unit]` with `PublishError.Closing` or `PublishError.Closed` when the context no longer takes events, and `publish` becomes a final method that throws `EventBusClosedException` for them, as before; `Events.tryPublish` publishes with the publisher in scope. Invalid listeners are found as `EventListenerError` and still stop the start with `InvalidEventListenerException`. Migration: implement `tryPublish` instead of `publish` in a custom `EventPublisher` (COILIX-00031).
- **BREAKING** Configuration errors are typed as `ConfigError` instead of thrown. The reading methods of `ConfigTree`, `ScalarReader.read`, `ConfigBinder.bind`, `ConfigFormat.parse`, `Profiles.active` and `EnvironmentLoader.load` return `Either[ConfigError, A]`. `Environment` gets `lookup`, `binding` and `evaluate`, and `ComponentProvider` gets `lookup`, which return `Either`, while `get`, `bind` and `resolve` still throw `ConfigurationException` with the same messages. `StartupError.Configuration` holds a `ConfigError`. A configuration file that cannot be parsed, a substitution without a value and malformed profiles now stop the start with a readable message and exit code 1, without a stack trace. Migration: return `Either` from custom implementations of these traits, implement `lookup`, `binding` and `evaluate` instead of `get`, `bind` and `resolve` in a custom `Environment` and `lookup` instead of `get` in a custom `ComponentProvider`, and add `.orThrow` (from `ConfigError`) where a value is needed directly (COILIX-00031).
- **BREAKING** Predictable errors of the container and of the startup are typed instead of thrown, and the top layer decides whether to raise them. `ContextError` (missing, ambiguous or circular dependencies, effectful beans without an interpreter, a failed bean creation) is returned by `CandidateSelector.choose`, `DependencyResolver.resolve` and `resolveLevels`, `ContextPlanner.plan` and `ApplicationContextBuilder.create`, and `StartupError`, which keeps a `ContextError` in `StartupError.Context`, by `BasePackageResolver.resolve`, `CoilixBootstrap.start`, `CoilixApplicationRunner.start` and `CoilixIOStartup.application`. Operations in a resource return `ResourceT[E, A]`, an `EitherT` over `Resource[IO, _]`. A `CoilixIOApp` that cannot start logs the error without a stack trace and exits with code 1. `build`, `CandidateSelector.select` and the testkit still throw the same exceptions. Migration: implement `choose` instead of `select` in a custom `CandidateSelector`, return `Either` or `ResourceT` from the other custom components, and use `ContextError.raised` or `StartupError.raised` where a `Resource` that fails is needed (COILIX-00031).
- **BREAKING** Coilix no longer runs `IO` outside a fiber while it starts and closes an application. `EffectInterpreter.interpret` returns `Resource[IO, BeanRegistry]` (`InterpretedBeans` is removed), `ApplicationContextBuilder.create`, `CoilixBootstrap.start` and `CoilixApplicationRunner.start` return a `Resource` released by `shutdown`, `RunnerAdapter.run` and `RunnerInvoker.invoke` return `IO[Unit]`, `StartupEvents.around` takes the runners as `IO` and leaves closing the context to its owner, and `TestContextFactory` gets `resource(setup)`, which `create` opens. `IORunnerAdapter` takes no runtime. Synchronous code runs `IO` only through `SynchronousLifecycle` (`opened`, `started`, `run`). Migration: return `IO` from custom runner adapters (`IO.blocking` for blocking calls), use the returned `Resource` with `use` or `SynchronousLifecycle.opened`, and implement `resource` instead of `create` in a custom `TestContextFactory` (COILIX-00031).
- **BREAKING** `ContextLifecycleListener.onContextStarted` and `onContextClosing` return `cats.effect.IO[Unit]`, and a `CoilixIOApp` runs them in `IO` without blocking. `ConfigurableApplicationContext` gets `start` and `shutdown` in `IO`, and `ApplicationContextBuilder.create` builds a context without starting it, while `build` and `close()` stay for code outside `IO`. Migration: wrap the bodies of listener methods in `IO` (`IO.blocking` for blocking calls), write `override def onContextClosing: IO[Unit]` without parentheses, and override `create` instead of `build` in a custom `ApplicationContextBuilder` (COILIX-00031).
- **BREAKING** The constructor of `ConfigPath` is private, so the component type always comes from a `ClassTag`. Migration: replace `ConfigPath("path", classOf[Component])` with `ConfigPath[Component]("path")` (COILIX-00028).
- **BREAKING** `BeanRegistry` gets `beanNames`, `defer` and `complete`, `ApplicationContext` gets `createdBeans`, and `ImmutableBeanRegistry` takes `BeanEntry` values and a `RegistryCompletion`. Migration: custom implementations of these traits add the new methods; code that walks all beans to find annotated methods uses `createdBeans` instead of `beanNames` with `getBeanByName`, so it does not create lazy beans (COILIX-00015).
- **BREAKING** `TaskExecutor` is now the compute pool of the application: one thread per processor (`coilix.concurrency.compute.threads`), instead of a virtual thread per task; with cats-effect in the core it is the work-stealing pool of cats-effect, named `io-compute-*` (COILIX-00031). Migration: replace `coilix.concurrency.executor.*` with `coilix.concurrency.compute.threads` and move blocking work to `BlockingExecutor` or `@Async(blocking = true)`. The default executor beans are left out when the application or a module provides its own executor of that type (COILIX-00005).
- `GracefulShutdown.logFailure` is replaced by `FatalErrors.guarded`, and `ExecutorServiceTaskExecutor`, `ScheduledExecutorTaskScheduler` and `NamedThreadFactory` take an optional handler of fatal errors (COILIX-00030).
- When an `ApplicationRunner` fails, the application closes the context and ends with an error, instead of leaving it open until the JVM stops (COILIX-00016).
- Startup log messages are now `Launching <app>` and `<app> is up after <n> s` (COILIX-00008).
- Artifacts are compiled with Scala 3.9 LTS for JDK 17, so they work with Scala 3.9 or newer and JDK 17 or newer (COILIX-00009).

### Fixed

- An exception thrown by the constructor of a bean or by a `@Bean` method now stops the startup with `BeanCreationException`, whose message names the class or method and the exception and whose cause is that exception. It escaped as the `InvocationTargetException` of reflection, with the real error only in its cause. A fatal error, such as `OutOfMemoryError`, is still rethrown as it is (COILIX-00003).
- The `@PostConstruct` and `@PreDestroy` methods of the object returned by a `@Bean` method now run also when the method declares a trait or a superclass, for example `def gateway: Gateway = HttpGateway()`. They were looked up only in the declared type, so such a bean was never initialized or closed (COILIX-00004).
- `@Qualifier("name")` on a constructor or `@Bean` method parameter now injects the bean with that name. It was documented as reserved and ignored. A missing name stops the startup with `NoSuchBeanException`, and `@Qualifier` on an `Option[T]` or collection parameter with `UnsupportedDependencyTypeException` (COILIX-00000).
- A bean with an `Option[T]` or `List[T]` dependency now receives every matching bean, not only the beans created before it. A cycle through an `Option[T]` dependency is now reported as `CircularDependencyException` (COILIX-00012).
- Several `@Bean` methods of one class that return the same type, such as two `DataSource` beans told apart with `@Qualifier`, are now all registered. Only one of them was kept when the application scanned its packages (COILIX-00003).
- A retry of an asynchronous event listener is no longer lost when its delay ends before the scheduling call returns, which happened under load with short delays. The lost retry never ran and kept the delivery pending, so `awaitIdle` and closing waited the whole timeout. A retry that cannot be scheduled because the bus is closing or the scheduler refuses it is now dropped with an `ERROR` log instead (COILIX-00016).
