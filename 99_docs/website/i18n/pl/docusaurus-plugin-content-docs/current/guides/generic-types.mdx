## Wstrzykiwanie po pełnym typie

Parametr konstruktora typu `PriceSource[Option]` dostaje tylko bean, który rozszerza `PriceSource[Option]`, więc `@Primary` ani `@Qualifier` nie są potrzebne:

<CodeBlock language="scala" title="PriceReport.scala">{PriceReport}</CodeBlock>

Tak samo działa `Option[PriceSource[List]]` i `List[PriceSource[Option]]`. Wildcard, jak w `List[PriceSource[?]]`, pasuje do każdego argumentu typu. `ApplicationContext.getBean[PriceSource[Option]]` i `bean[PriceSource[Option]]` z testkitu też szukają beanów po pełnym typie.

## Ograniczenia

Coilix czyta argumenty typów z sygnatur generycznych, które zapisuje kompilator, więc niektórych typów nie da się dopasować. Start kończy się wtedy błędem z nazwą parametru:

- Zmienna typu, której nic nie wiąże, jak w `final class SqlPrices[F[_]](source: PriceSource[F])`. Taką klasę tworzy się w metodzie `@Bean` z konkretnym typem, np. `def prices: PriceSource[Option] = SqlPrices[Option]()`.
- Lambda typu albo typ częściowo zastosowany, np. `PriceSource[[A] =>> Either[String, A]]`, bo JVM zachowuje z niego tylko `Either`. Zamiast tego zadeklaruj nazwaną klasę dla efektu.

Gotowa instancja zarejestrowana tylko z klasą, bez argumentów typów, nie pasuje do zależności z argumentami typów. Zarejestruj ją z pełnym typem, tak jak robi to `RegisteredBean.of[PriceSource[Option]](...)`.
